## 데이터와 실제 검증 범위

### 식품안전나라 I1250

공식 문서: https://www.foodsafetykorea.go.kr/api/openApiInfo.do?svc_no=I1250

검색 요청 필드: PRDLST_NM, PRDLST_REPORT_NO, LCNS_NO, PRDLST_DCNM, BSSH_NM.

보고일자 원본은 PRMS_DT이다. 공식 문서의 요청 항목은 보고일자, 출력 설명은 허가일자로 표기되어 있어 원본 값을 그대로 표시했다. 영양성분의 FOOD_CAT1_NM을 I1250 식품유형 PRDLST_DCNM으로 추정하지 않는다.

공식 sample/I1250/json/1/5를 직접 호출하여 INFO-000, row 배열과 실제 검색·표시 필드를 확인했다. 이 샘플 성공은 소유자의 인증키/활용신청/운영 서버 검색 검증을 뜻하지 않는다.

이용조건 확인: 서비스별 활용신청과 인증키 필요. I1250 메타정보 호출제한은 2,000으로 표시되어 있으나 그 항목에 시간 단위는 명시되어 있지 않다. 오류 설명에는 비증분 시간당 100회, 06~19시 인증키/서비스별 300회, 1회 최대 1,000행 등 제한이 별도로 제시되어 있다. 계정별 실제 허용량을 운영 전에 확인해야 한다. 현재 코드는 5분 검색 캐시로 같은 검색의 페이지·필터 변경 시 재수집을 줄인다.

서비스 신청 절차: https://www.foodsafetykorea.go.kr/api/howToUseApi.do?menu_grp=MENU_GRP34&menu_no=687

출처표시와 자료별 권리 확인 근거: https://www.mfds.go.kr/wpge/m_34/de010803l001.do

공식 공개 안내와 저작권정책까지 확인했다. 로그인 후 동의하는 신청 약관 전체나 해당 계정의 승인 조건까지 확인한 것은 아니다. 화면에 공식 출처를 표시하며 공공기관 공식 사이트로 표현하지 않는다.

### 식약처 식품영양성분DB

공식 문서: https://www.data.go.kr/data/15127578/openapi.do

공식 상세 페이지 HTML에 포함된 Swagger 원문에서 다음 출력 속성을 확인했다. 검증한 속성의 발췌를 nutrition-official-fields.json에 보관했다.

| 필드 | 공식 의미 |
|---|---|
| ITEM_REPORT_NO | 품목제조보고번호 |
| FOOD_CAT1_NM | 식품대분류명 |
| AMT_NUM1 | 에너지(kcal) |
| SERVING_SIZE | 영양성분함량기준량 |
| FOOD_CD | 식품코드 |

호출 주소: https://apis.data.go.kr/1471000/FoodNtrCpntDbInfo03/getFoodNtrCpntDbInq03

공식 요청변수 ITEM_REPORT_NO로 조회하고 응답의 품목번호도 정확히 일치해야 한다. 1개의 일치 자료만 인정한다. 복수 일치, 누락, 100건을 넘는 불완전한 조회, 인증·통신 오류는 미제공으로 처리한다. 이름 유사도나 같은 식품유형의 영양값으로 대체하지 않는다. 0 kcal는 유효값으로 유지하며, 기준량이 없으면 기준량 미제공이라고 표시한다. 한 페이지 영양정보 조회는 최대 3개 동시 요청, 총 12초 예산을 사용하며 오류 시 제품 목록은 계속 표시한다. 영양 캐시는 정상 1시간, 오류 30초다.

무료·이용허락범위 제한 없음으로 공시되어 있다. 개발계정 트래픽 10,000, 개발 자동승인/운영 수동심사로 표기되어 있으며, 실제 활용신청 가능 상태와 허용량은 계정에서 확인해야 한다. 별도 서버 환경변수 MFDS_NUTRITION_API_KEY에 **공공데이터포털의 디코딩 인증키**를 설정한다. 식품안전나라 키와 다른 인증체계다. 코드의 URLSearchParams가 URL 인코딩하므로 인코딩된 키를 그대로 넣지 않는다.

이번 환경에는 해당 실제 인증키가 없다. 영양 API의 인증된 실제 제품 응답과 매칭률은 미검증이며, 공식 명세와 모의 응답으로 검증했다. 키 미설정 시 미제공 표시가 정상 동작한다. 체험 모드는 영양 API를 호출하지 않는다.

## 제한과 후속 검증

50행 고정 제한은 제거했다. 다만 API 호출량과 메모리를 제한하고 전체 정렬·필터의 정확성을 유지하기 위해 검색당 원본 수신행 합계 5,000행까지만 완전 수집한다. 전체 항목 검색은 중복 제거 전 다섯 필드의 수신행 합계 기준이다. 초과하면 HTTP 422와 범위를 좁히라는 안내를 반환하고 일부 결과를 전체 결과로 노출하지 않는다. 넓은 식품유형/제조사 검색은 이 제한에 걸릴 수 있다. 무제한 전체 데이터 검색이 필요하면 증분 동기화한 별도 검색 DB가 추가로 필요하다.

공식 API의 정렬/스냅샷 고정 옵션은 문서에서 확인되지 않았다. 5분 캐시는 확보 후 페이지 안정성을 높이지만, 원본을 여러 번 수집하는 도중에 원본 자체가 바뀌는 상황까지 보장하지는 않는다.

## 배포 상태와 적용 절차

이번 작업은 로컬 코드 수정과 전달용 ZIP 작성까지 완료했다. GitHub 원격 커밋/푸시, PR 생성, Render/Vercel 배포, 운영 환경변수 변경은 **하지 않았다**. 운영 서비스가 변경되었다고 볼 근거가 없다.

적용 시 기존 프로젝트에서 Vercel 중계와 Render 서버를 함께 갱신해야 한다. 새 서명에 시작 행이 추가되어 기존 0.4 중계와 혼용할 수 없다. Vercel에 먼저 새 중계를 올리고 Render를 곧바로 갱신하는 점검 구간을 잡거나 별도 프리뷰로 함께 검증한 뒤 전환한다. 롤백도 양쪽을 같은 버전으로 되돌린다. 운영 API 키는 ZIP에 포함하지 않았다.

Render: 기존 FOODSAFETY_API_KEY, FOOD_FINDER_BRIDGE_URL 유지. 영양정보 사용 시 MFDS_NUTRITION_API_KEY 추가. Vercel: FOODSAFETY_API_KEY는 Render와 동일해야 한다. lib/search.js를 포함한 전체 소스를 배포해야 중계가 동작한다.

배포 후 /health 버전 0.6, /diagnostics, 다섯 검색 필드, 100건 이상 실제 검색의 페이지 중복·누락, 영양정보 실제 일치 제품/없는 제품/키 오류를 확인해야 운영 검증 완료다.

## 8. ‘식품구매검색’ 한글 도메인 — 검토만

가능한 형태는 식품구매검색.kr 또는 식품구매검색.한국 같은 완전한 주소다. 한글 국가 도메인 운영 근거: https://krnic.kisa.or.kr/jsp/statboard/domain/reg/currentKorean.jsp

주소창에 접미사 없는 ‘식품구매검색’만 입력했을 때는 일반적으로 브라우저 검색으로 처리된다. 도메인을 등록해도 모든 브라우저에서 이 단어만으로 자동 접속하도록 강제할 수 없다. 검색 결과 노출은 별도의 사이트 등록/색인과 검색엔진 판단에 따른다.

예상 절차:

1. 등록대행자에서 원하는 완전한 주소의 등록 가능 여부·비용·갱신 조건 확인
2. 원하는 주소 등록
3. 한글 주소를 Punycode로 변환한 값을 기존 Render 서비스 Custom Domains에 추가
4. Render가 안내하는 DNS 레코드를 도메인 업체에 설정하고 소유 확인
5. HTTPS 발급 및 원래 사이트와의 접속 확인. 필요하면 대표 주소로의 리디렉션 설정

Render 공식 가이드는 유니코드 도메인의 Punycode 변환, 도메인 추가→DNS 설정→검증, 자동 TLS를 안내한다: https://render.com/docs/custom-domains

DNS 유형은 루트 도메인과 제공 업체에 따라 달라지므로 연결 전 실제 안내를 사용한다: https://render.com/docs/configure-other-dns

등록 가능 여부·가격은 조회하거나 확정하지 않았다. 도메인 구매, DNS 변경, Custom Domain 추가, 리디렉션 설정은 모두 실행하지 않았다.
